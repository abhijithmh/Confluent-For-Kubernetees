# Confluent Platform RBAC Restoration & User Setup Guide

This guide details the exact steps and operational commands required to back up, restore, and maintain OpenLDAP users and Confluent Platform Role-Based Access Control (RBAC) rolebindings when redeploying a **Confluent For Kubernetes (CFK)** cluster.

---

## 1. Architecture Overview: How RBAC & Identity Work in CFK

RBAC in CFK is powered by three main components:

1. **Identity Provider (OpenLDAP)**:
   - Contains user identity entries (`inetOrgPerson`) and group entries (`groupOfNames`).
   - Declaratively bootstrapped via ConfigMap `ldap-init-configmap` ([01-infrastructure.yaml](file:///home/ubuntu/Dev/CFK/01-infrastructure.yaml)).

2. **Confluent Metadata Service (MDS)**:
   - Embedded inside CP Server Kafka brokers (listening on HTTP port `8090`).
   - Authenticates users against OpenLDAP and stores active rolebindings in the internal Kafka topic `_confluent-command`.

3. **Declarative Kubernetes CRDs (`ConfluentRolebinding`)**:
   - Defined in [05-rbac-rolebindings.yaml](file:///home/ubuntu/Dev/CFK/05-rbac-rolebindings.yaml).
   - CFK operator reconciles `ConfluentRolebinding` CRDs against MDS automatically.

```
[ OpenLDAP ] ◄── Authentication ── [ CP Server MDS (:8090) ] ◄── Role Sync ── [ CFK Operator ]
     ▲                                      ▲                                        ▲
     │                                      │                                        │
 (01-infrastructure.yaml)           (_confluent-command)                     (05-rbac-rolebindings.yaml)
```

## 2. Step-by-Step Restoration Procedure on Cluster Redeployment

When redeploying the cluster (or re-creating the Kafka brokers), follow these 6 steps to ensure all users and permissions are completely restored without ghost historical cluster IDs.

### Step 1: Query Current OpenLDAP Users
Before redeploying or adding new users, inspect existing LDAP users:

```bash
kubectl exec -n confluent deployment/openldap -- \
  ldapsearch -x -H ldap://localhost:389 \
  -b "ou=users,dc=example,dc=com" \
  -D "cn=admin,dc=example,dc=com" \
  -w adminpassword "(objectClass=inetOrgPerson)" cn
```

---

### Step 2: Ensure Declarative OpenLDAP User Bootstrap
All users must be declared in the OpenLDAP initialization LDIF ConfigMap in [01-infrastructure.yaml](file:///home/ubuntu/Dev/CFK/01-infrastructure.yaml):

```yaml
dn: uid=dev_user,ou=users,dc=example,dc=com
objectClass: inetOrgPerson
objectClass: organizationalPerson
objectClass: person
objectClass: top
cn: dev_user
sn: Developer
uid: dev_user
userPassword: devpassword
```

*(To add users dynamically to a running LDAP pod without restarting:)*
```bash
kubectl exec -i -n confluent deployment/openldap -- \
  ldapadd -x -H ldap://localhost:389 \
  -D "cn=admin,dc=example,dc=com" \
  -w adminpassword <<EOF
dn: uid=newuser,ou=users,dc=example,dc=com
objectClass: inetOrgPerson
objectClass: organizationalPerson
objectClass: person
objectClass: top
cn: newuser
sn: User
uid: newuser
userPassword: newpassword
EOF
```

---

### Step 3: Define Declarative `ConfluentRolebinding` CRDs
In [05-rbac-rolebindings.yaml](file:///home/ubuntu/Dev/CFK/05-rbac-rolebindings.yaml), define rolebindings using `kafkaRestClassRef.name: default`.

> [!IMPORTANT]
> **Do NOT hardcode `clustersScopeByIds.kafkaClusterId`**.
> Leaving `clustersScopeByIds.kafkaClusterId` unassigned allows CFK operator to dynamically resolve the new base64 KRaft Cluster ID generated by CP Server on redeployment.

Example `ConfluentRolebinding` definitions:

```yaml
# 1. SystemAdmin for Admin User
apiVersion: platform.confluent.io/v1beta1
kind: ConfluentRolebinding
metadata:
  name: admin-system-admin
  namespace: confluent
spec:
  principal: User:admin
  role: SystemAdmin
  kafkaRestClassRef:
    name: default

---
# 2. DeveloperRead for Dev User
apiVersion: platform.confluent.io/v1beta1
kind: ConfluentRolebinding
metadata:
  name: dev-user-developer-read
  namespace: confluent
spec:
  principal: User:dev_user
  role: DeveloperRead
  kafkaRestClassRef:
    name: default
  resourcePatterns:
    - resourceType: Topic
      name: "*"
      patternType: LITERAL

---
# 3. SystemAdmin for Schema Registry
apiVersion: platform.confluent.io/v1beta1
kind: ConfluentRolebinding
metadata:
  name: admin-schemaregistry-system-admin
  namespace: confluent
spec:
  principal: User:admin
  role: SystemAdmin
  kafkaRestClassRef:
    name: default
  clustersScopeByIds:
    schemaRegistryClusterId: id_schemaregistry_confluent
```

---

### Step 4: Apply RBAC Rolebindings
Apply the declarative rolebindings file:

```bash
kubectl apply -f /home/ubuntu/Dev/CFK/05-rbac-rolebindings.yaml
```

---

### Step 5: Purge Historical / Stale MDS Rolebindings
If legacy cluster IDs (e.g. `"confluent"` or old base64 cluster IDs) appear in Control Center UI or MDS API lookup, purge them directly via MDS REST API:

#### A. List Active Rolebindings for a Principal:
```bash
kubectl exec -n confluent kafka-0 -- \
  curl -s http://localhost:8090/security/1.0/lookup/rolebindings/principal/User:dev_user \
  -u admin:adminpassword
```

#### B. Delete Stale Rolebinding Entry:
```bash
kubectl exec -n confluent kafka-0 -- \
  curl -X DELETE -s "http://localhost:8090/security/1.0/principals/User:dev_user/roles/SystemAdmin/bindings" \
  -u admin:adminpassword \
  -H "Content-Type: application/json" \
  -d '{
    "scope": {
      "clusters": {
        "kafka-cluster": "confluent"
      }
    }
  }'
```

---

### Step 6: Verify User Access & RBAC Setup

#### 1. Verify via MDS API:
```bash
kubectl exec -n confluent kafka-0 -- \
  curl -s http://localhost:8090/security/1.0/lookup/rolebindings/principal/User:admin \
  -u admin:adminpassword
```

#### 2. Verify via Control Center UI:
- Open `http://32.196.166.41:30021` in browser.
- Login with `admin` / `adminpassword`.
- Navigate to **Administration** -> **Role Assignments**.
- Confirm that active cluster ID matches runtime KRaft Cluster ID (e.g. `ZGY4MzQyZTItNjYxMC00OQ`) and no duplicate inactive clusters exist.

## 3. Recommended Disaster Recovery Checklist

| Task | Command / Manifest Location | Frequency |
|---|---|---|
| **Backup LDAP Users** | `01-infrastructure.yaml` (`ldap-init-configmap`) | On User Add/Delete |
| **Backup Rolebindings** | `05-rbac-rolebindings.yaml` | On Role Change |
| **Re-Sync Master File** | `cat 01* 02* 03* 04* 05* 06* > all-in-one/00-all-in-one.yaml` | After Any Edit |
| **Verify MDS Binding** | `curl http://localhost:8090/security/1.0/lookup/...` | Post Redeployment |
